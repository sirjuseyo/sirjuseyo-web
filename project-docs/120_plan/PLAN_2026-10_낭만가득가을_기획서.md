**매뉴얼 §11 표준 절차**
```bash
git checkout dev
git pull origin dev
git checkout -b feature/{작업설명}
```

**이 레포 적용값**

| 항목 | 값 | 근거 |
|---|---|---|
| 분기 기준 | `dev` (매뉴얼 §5-4 "`dev`에서 `feature/*` 분기") | 매뉴얼 §5 |
| 브랜치명 | `feature/T-169-oct-loan-page` | 매뉴얼 §4-2 `feature/{프로젝트번호}-{작업설명}` + 이 레포 확정 패턴 `feature/T-{T-ID번호}-{작업설명}`(TODO_BOARD 인수인계 Q2). 선배도 기획서 T-156이 아닌 **구현 T-ID 기준**으로 `feature/T-157-sep-loan-page`를 만들었으므로 동일하게 구현 T-ID 기준. ⚠️ **T-168은 W-168(과거 월 워딩 제거)에 소모**되므로 10월 페이지 생성 T-ID는 **T-169** |
| 커밋 메시지 | `feat(2-0)` / `fix(2-0)` / `docs(ops)` 형식 | 매뉴얼 §10 |
| 머지 후 | 머지 완료된 `feature/*`는 로컬/원격 모두 삭제 원칙 | 매뉴얼 §9 |

**현재 로컬 상태 실측 (2026-09-29, `git fetch origin --prune` 후)**

| 항목 | 상태 | 판정 |
|---|---|---|
| 로컬 `dev` vs `origin/dev` | **0 ahead / 20 behind** | ✅ **fast-forward 가능** → `git pull origin dev` 안전. TODO_BOARD 정책 "최신화는 fast-forward 가능한 미반영 커밋만 반영" 충족 |
