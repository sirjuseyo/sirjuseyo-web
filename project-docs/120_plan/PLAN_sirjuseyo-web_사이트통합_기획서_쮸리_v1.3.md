## 1. 통합 개요

### 목표
- `https://www.sirjuseyo.com/` 메인 페이지를 `monthly-loan-repo/index.html`로 교체
- 두 워크스페이스(`sirjuseyoWeb`, `monthly-loan-repo`)를 `sirjuseyo-web` 레포 하나로 통합

### 도메인 전략
- **서브도메인 없음** (GitHub Pages는 레포당 커스텀 도메인 1개 제한)
- 모든 페이지를 `https://www.sirjuseyo.com/~` 메인 도메인에 이어서 구성
- CNAME: `sirjuseyo.com` 유지 (sirjuseyo-web 레포 기준)
- **`monthly-loan.sirjuseyo.com` 끊김 감수. 리다이렉트 걸지 않음.**
  (사유: 사용자가 답답하면 톡으로 재유입 — 대표이사 결정)

### 레포 통합 방식

| 항목 | 현재 | 통합 후 |

## 3. 사이트맵 (메뉴 구조)

### 3-0. 햄버거 메뉴 규칙 ★v1.2 확정 (미결④ 종결)

#### 원칙: 햄버거는 1Depth만 노출한다

메뉴 안에서 아코디언으로 하위를 펼치지 **않는다.** 1Depth 항목을 누르면 **해당 대표 페이지로 이동**하고, 2Depth 항목은 **그 페이지 본문에서 카드/목록으로** 보여준다.

> 사유: 챌린지·아카이브처럼 하위가 수십~수백 개로 늘어날 수 있는 메뉴를 아코디언으로 펼치면 햄버거가 감당 못 한다. 1Depth로 통일하면 하위 개수와 무관하게 메뉴는 항상 7줄.

#### 1Depth 클릭 동작

| 1Depth 메뉴 | 이동 경로 | 그 페이지 본문(2Depth) |
|-------------|-----------|------------------------|
| 써주세요. 소개 | `/home/` | 없음 |
| 인기 상품은 나노크레딧 | `/nanocredit/` | 10·20·30·50·소통거리 카드 |
| 나에게 맞는 대출 방식 | `/loan-match/` | 신용왕·쇼핑왕·평판왕·기여왕 카드 |
| 월별 대출 신청하기 | `/{CURRENT_MONTH}/` | 없음 (→ 신청서로 연결) |
| 챌린지 | `/challenge/` | 챌린지 목록 (100개여도 여기 스크롤) |
| 아카이브 | `/archive/` | 검사기·Deep Dive 등 목록 |
| 공지사항 | `/notice/` | 공지 목록 |

#### 구현 방식

- 2Depth 항목 = **메뉴가 아니라 대표 페이지의 콘텐츠**(카드/버튼/목록)
- 아코디언 펼침 **미사용**
- 메뉴 순서·클릭 스타일은 위 기본값으로 구현. **치명적 원칙 아님 — 구현 후 조정 가능**

#### 신규 제작 필요 — 대표 페이지 3개

2Depth를 담을 대표 페이지가 없는 메뉴:

| 메뉴 | 대표 페이지 | 현재 상태 |
|------|-------------|-----------|
| 나노크레딧 | `nanocredit/index.html` | ✅ 존재 |
| 나에게 맞는 대출 방식 | `loan-match/index.html` | ✅ 존재 |
| **챌린지** | `challenge/index.html` | ❌ **신규 제작** — 현재 챌린지가 `2026-06/worldcup-challenge/`에 흩어짐, 묶는 페이지 없음 |
| **아카이브** | `archive/index.html` | ❌ **신규 제작** — 항목들이 분산, 묶는 페이지 없음 |
| **공지사항** | `notice/index.html` | ❌ **신규 제작** — 앱 고객센터 공지 공유(§3-7). 서버 커스터마이징 필요 |

> **이 3개(challenge / archive / notice) 제작은 통합(W-073) 이후 별도 구현 과제.**

#### 페이지 흐름

```
매월 바뀜   /2026-08/index.html      안내 페이지 (카피·이벤트명·OPEN 배너)
             └ [신청하기] 버튼

고정        /apply/apply.html         대출 신청서 (Q1~Q6 단계 입력)  ← 안 바뀜
                    ↓
고정        monthly-api.sirjuseyo.com/api/monthly-loan/applications  ← 서버팀 API. 안 바뀜
```

#### apply.html 성격 — 월별 대출 종속 고정 페이지

| 항목 | 값 |
|------|-----|
| 역할 | 대출 신청 폼. "신청하기" 클릭 시 열림 |
| 월 하드코딩 | **없음** (매월 바뀌지 않음) |
| 참조 스크립트 | `/footer.js`, `/js/legal-shared.js` (**절대경로 — 위치 이동에 안전**) |
| 제출 API | `monthly-api.sirjuseyo.com` (별개 서브도메인. **통합·archive 영향 없음**) |
| 외부 배포 | **없음.** 신청서 주소를 카톡·문자·앱에 직접 뿌린 적 없음 (대표이사 확인) |
| 성격 | **월별 대출에 종속되어 존속하는 페이지.** 통합 후에도 유지 |

> `monthly-loan.sirjuseyo.com/apply/apply.html`을 직접 뿌린 적 없으므로, 서브도메인 archive로 인한 신청서 유입 차단 리스크 **없음.**

#### 매월 관리 방식 — menu.js 단일 소스 ★확정

매월 바뀌는 것은 **안내 페이지 링크 하나뿐**이다. (신청서·API는 고정)
햄버거 메뉴를 페이지마다 박지 않고 **공유 JS(`menu.js`) 한 곳에서 관리**한다. (`footer.js`와 동일 패턴)

```js
// menu.js 최상단
const CURRENT_MONTH = '2026-07';   // ← 매월 이 한 줄만 수정
```

- 메뉴가 이 값을 읽어 "월별 대출 신청하기" 링크를 `/${CURRENT_MONTH}/`로 생성
- 페이지가 N개여도 **수정 지점은 1곳**
- 까먹으면 지난달 페이지가 뜬다 — **단, 404는 나지 않음**

#### 매월 배포 순서 — 폴더 먼저, 링크 나중 (역순 금지)

```
1. 2026-08/ 폴더 생성 + 안내 페이지 완성   ← 콘텐츠 먼저
2. menu.js  CURRENT_MONTH = '2026-08'      ← 링크 나중
3. 로컬 확인 → 커밋 → 푸시
```

| 순서 위반 | 결과 |
|-----------|------|
| 링크만 먼저 바꿈 (폴더 없음) | **404 — 신청 불가 (최악)** |
| 폴더만 만듦 (링크 안 바꿈) | 지난달 페이지 노출 |

> **주의:** menu.js·매월 배포 순서는 **햄버거 메뉴 구현 단계**에서 적용한다. 이번 통합(W-073) 범위가 아니라, 구현 시 따를 규칙으로 확정해 둔 것.

### 3-7. 공지사항 ★v1.3 확정 (미결⑤ 종결)
- **경로 (통합 후):** `/notice/`
- **방식:** 앱 고객센터 공지 **공유** (앱 공지 = 웹 공지)

#### 배경 — 관리자모드에 공지 기능 이미 존재

`admin.sirjuseyo.com` 관리자모드 → **고객센터 → 공지사항 관리** 메뉴가 이미 운영 중.
단, 이 공지사항은 **써주세요. 앱과 연동된 고객센터**이며, 현재 **앱 전용**이다.

#### 확정 — 앱 공지를 웹과 공유한다

| 항목 | 내용 |
|------|------|
| 저장소 | **앱 서버** (기존. 새로 안 만듦) |
| 등록 | **관리자모드 [공지사항 관리]** (기존) |
| 웹 화면 | `notice/index.html` — **신규 제작** |
| 공유 범위 | 앱·웹이 **같은 공지**를 본다 (점검·약관·금리 변경 등 회사 공지) |

```
관리자모드 [공지사항 관리]에서 공지 등록
        ↓
      앱 서버 저장 (기존)
        ↓
앱          웹 /notice/
(기존)      → 앱 공지 API 호출 → 게시판 렌더  ← 웹 화면만 신규
```

#### ⚠️ 커스터마이징·개발 필요 (공유의 대가)

앱 전용 공지를 웹과 공유하려면 **그냥 갖다 쓸 수 없고 손봐야 한다.**
